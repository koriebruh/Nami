### Crypto, secrets and outbound requests

- Ruling: the sealed format is fixed before UP-10 writes any ciphertext (UP-9 hardening round): `version(1) || nonce(12) || ciphertext || tag(16)`, version byte `0x01`, AES-256-GCM with a random 96-bit nonce per value. The master key (`NAMI_ENCRYPTION_KEY`, 32 bytes base64) is never an AES key: the AEAD key is its HKDF-SHA256 subkey for info `nami/aead/v1`, which `derive_subkey` refuses to hand out (other primitives take their own, e.g. `nami/hmac/v1`). The associated data is `version || context`, with a per-row context `<table.column>:<monitor id>` (`monitors.request_headers:<id>`, `monitors.auth_password:<id>`): a value cannot open as another column, a ciphertext copied to another row does not open, and the version is authenticated. Unknown version or a value too short for version + nonce + tag is rejected before decryption. Intermediates are zeroized. `main` refuses the built-in `TEST_KEY`; a missing or malformed key stops startup. A layout, KDF or AAD change needs a new version byte with v1 still readable — cost if wrong: re-encrypt rows.
- Ruling: secrets (custom header values, basic-auth password) are write-only for everyone: the API returns `value_set` / `has_auth_password` only. Header lists are all-or-nothing on write (the UI asks for every value on any edit). Writes are JSON-only; decryption failure makes the check Down with a fixed message, never the plaintext.
- Ruling: viewer redaction (beyond the spec, ratified): viewers read `***` for URL secrets (userinfo, query values, fragment), the request body, the basic-auth username and the UDP payload. Every monitor view carries `redacted: true|false` and clients decide on that flag, never on the text (a literal `***` in a member's URL stays editable) — cost if wrong: viewers cannot read bodies.
- Ruling: outbound destination policy is default-allow (self-hosted; private and loopback targets are legitimate) but these are always refused by every check type: link-local `169.254.0.0/16` and `fe80::/10` (cloud metadata), `fd00:ec2::254`, Alibaba Cloud metadata `100.100.100.200` (CGNAT `100.64.0.0/10` as a whole stays allowed), "this network" `0.0.0.0/8` and `::`, including IPv4-mapped (`::ffff:a.b.c.d`) and NAT64 (`64:ff9b::a.b.c.d`) forms and decimal/hex spellings. Refusal text: `destination not allowed`. The refusal is checked at check time (the API accepts such a monitor). No DNS-rebinding window: every probe connects to exactly the addresses it judged (`GuardedResolver` for HTTP; tcp/udp/ping/mail/tls resolve once). dns monitors look up names only: IP literals are rejected (`host must be a domain name to look up`, including every IP spelling `url::Host::parse` accepts); an explicit `dns_nameserver` is judged too.
- Ruling: every HTTP client keeps `.no_proxy()` (an environment proxy would bypass the destination guard) and `pool_max_idle_per_host(0)`. Clients are built lazily per slot. TLS resumption is off for expiry checks and `CheckContext` is built per pass, so a resumed session cannot skip certificate verification.
- Ruling: origin = scheme + host + port, compared as browsers do (default port implied). A check that carries secrets (custom headers, basic auth, credentials in the URL) or a request body (POST/PUT/PATCH) follows only redirects that stay on the monitored origin; anything else goes Down with `headers, credentials and request bodies are only sent to the monitored origin, so the redirect to <host or origin> was not followed`. An http→https redirect of such a monitor is a change of origin and goes Down too: point the monitor at the final URL (the form hints at it). Down rather than evaluating the 3xx, so an Up never hides that the real endpoint is not checked. Body counts as secret-bearing since the final wave (a 307/308 would re-post it).
- Ruling: secrets stay where they were entered. A PATCH that moves the URL to another origin, or turns `verify_ssl` off on an https URL (scheme compared case-insensitively), must enter every stored header value and the password again or clear them; otherwise 400 (`changing the url's scheme, host or port requires entering the header values and password again, or clearing them`, and a `turning off certificate verification ...` variant). Path or query changes on the same origin keep secrets. The UI takes "Keep" away in that case. Without this a project member could exfiltrate an admin's write-only secrets by retargeting the URL (reproduced live, fixed in #58) — cost if wrong: one extra re-entry on origin edits.
- Ruling: basic auth or credentials in the URL, not both (400); basic auth or an `Authorization` header, not both. Header lists: no blank value (`header {name}: enter a value`), no name repeated ignoring case (`header {name} is listed twice`), and `Host`, `Content-Length`, `Transfer-Encoding`, `Connection`, `TE`, `Upgrade`, `Keep-Alive`, `Proxy-Connection`, `Trailer`, `Expect` are reserved. A blank value used to wipe a stored secret silently.
- Ruling: `write_config` binds `project_id`, so the statement itself cannot cross tenants; `Monitor`'s hand-written `Debug` prints `<sealed>` / `<set>` and never the body or username.

### Behaviour

- Ruling: recovery threshold (`recovery_threshold`, default 1) counts consecutive successes while Down; editing what is checked (a reschedule) or resuming a paused monitor zeroes both `consecutive_failures` and `consecutive_successes`; a rename does not.
- Ruling: expiry monitors: ssl_expiry threshold default 14 days, domain_expiry 30 days; exactly N days left counts as Down (inclusive); `confirmation_threshold` defaults to 1 for expiry types; the threshold resets on a type switch; RDAP via `RDAP_BASE_URL` (default `https://rdap.org`), event parsing is tolerant, the body is capped.
- Ruling: default ports follow the type: a stored port that was the default of the old (type, `use_tls`) follows a type or `use_tls` change to the new default (smtp 25→465, pop3 110→995, imap 143→993); a chosen port (e.g. 2525) stays.
- Ruling: maintenance windows suppress incidents and alerts: a covered monitor's state machine is frozen (only `last_checked_at` moves, both counters untouched); a covered heartbeat is re-anchored (`outage_anchor_at = now()`) in the sweep transaction so it does not go Down at the first sweep after the window ends. Windows are project-wide or per-monitor, one-off (at most 366 days) or weekly (days_of_week, local start/end, IANA timezone; midnight wrap and DST gaps/repeats handled); overlapping windows = any; coverage helpers take only an `ActiveWindows` newtype.
- Ruling: monitor groups: `group_id` on monitors and heartbeats (composite FK `(group_id, project_id)`), order by `position` (max 1,000,000), group names are not unique (product choice).
- Ruling: tenant isolation by composite FKs `(monitor_id, project_id)` plus app checks: a foreign group or monitor id is 404, a non-member is 403 (never 404), viewers cannot write.
- Ruling: UI: all 11 check types in the form, request-config editor, group and maintenance badges, maintenance-windows page and groups in settings, two-step delete. Edit pages send `Cache-Control: private, no-store`. On edit, blank nullable numbers are sent as `null` so the engine resets them to the type default.

## Limits and environment

- `NAMI_ENCRYPTION_KEY` (required, base64 of 32 random bytes, `openssl rand -base64 32`): the engine refuses to start without it or with the test key. Back it up; secrets under a lost key cannot be recovered.
- `RDAP_BASE_URL` (default `https://rdap.org`): domain-expiry lookups.
- Ping monitors use unprivileged ICMP sockets. On Linux and in Docker the engine's group must be inside `net.ipv4.ping_group_range` (documented in `.env.example`; not yet wired into a compose service, see Deferred).
- Check types (11): http, keyword, tcp, ping, dns, ssl_expiry, domain_expiry, smtp, pop3, imap, udp. DNS record types: A, AAAA, CNAME, MX, TXT, NS.
- Request config: methods GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS (body only on POST/PUT/PATCH); body <= 64 KiB; <= 20 headers; header name <= 256 B, value <= 1024 B; basic-auth username <= 256 chars, password <= 1024 B; URL <= 2048 B; keyword <= 1024 B; expected value (dns/mail) <= 1024 B; UDP payload <= 1024 B, UDP reply read <= 16 KiB; mail greeting read <= 512 B, quoted <= 100 chars.
- Checker: HTTP body read <= 1 MiB, <= 10 redirects, error text <= 256 chars (control characters stripped), expected status range (`expected_status_min`/`max`), `follow_redirects` and `verify_ssl` toggles.
- Quotas: at most 200 maintenance windows and 200 monitor groups per project (400, `a project can have at most 200 maintenance windows: delete one first`, same for groups). Counted under the insert.
- Migrations used: 0012-0019 (Phase 2 range 0012-0029).
